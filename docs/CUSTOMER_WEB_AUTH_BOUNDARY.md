# Customer Web authentication boundary

**Production CUSTOMER browser authentication is disabled.** The real OW-P0-03 APIM POC is not accepted; issues #13/#14 were verified open on 25 October 2026. No environment flag enables production authentication.

Customer Web owns a typed `WebSessionAdapter` and CustomerSession; it imports no Operations/MANAGER implementation. Compatible narrow protocol: challenge start; stripped `{access_token,token_type,expires_in,user_id}` grant; adapter-backed cookie refresh; confirmed logout. Extra fields, including refresh_token, are rejected. Rejection cannot undo exposure from a misconfigured gateway, so real acceptance remains mandatory.

No concrete production APIM adapter is composed or added here. Production uses unavailableAdapter, null origin and zero protected network requests. Session and business clients are independently implemented/tested with injected interfaces. Future concrete Customer adaptation must satisfy its own approved configuration and security acceptance. Studying the Operations adapter does not make its Manager-specific code suitable for import.

Access tokens live only in private memory fields. No refresh credential, cookie reading, storage API, raw mobile OTP workaround, JWT role decoding or role assertion is used. `/v1/auth/me` must establish matching current CUSTOMER membership; MANAGER/RIDER alone cannot enter. Concurrent 401s share one refresh, recheck principal and replay once; pre-expiry refresh counts toward the bound. 403 never refreshes. Refresh owner mismatch or membership loss clears session. Requests, response bodies and adapter waits are bounded to 15 seconds; cancellation/epochs reject late responses.

Logout immediately clears token/principal, aborts work, changes epoch, cancels/clears QueryClient and removes protected forms/checks/commands. Lost logout blocks login/resume until explicit confirmed retry. Lost/invalid verify also requires confirmed cleanup before new login. The future adapter must serialize cookie-mutating actions across tabs and prevent late Set-Cookie overtaking logout. A caller timeout alone does not prove cookie ordering; no production flow relies on an unproven guarantee.

Business HTTP uses exact HTTPS origin, Bearer, credentials omit, no-store, redirect error, no-referrer, strict DTOs and safe error copy. No role assertions, credentials or household payloads enter URLs/logs/analytics. Query keys include owner/epoch, cache is memory-only, and automatic retries/focus/reconnect fetches are disabled. Previous protected data is hidden during loading/error. Prepared writes retain exact immutable body/key and owner/epoch across account navigation. No implicit account switch or document-persistent personal data.

Development fixtures require Vite serve/development/not-preview **and** the explicit fixture flag. Every build defines that server constant false, including NODE_ENV=development. Both build modes with fixture flag true are checked for fixture sentinel, identity, token, host and address exclusion. Fixture admission is explicitly labelled CUSTOMER-only and uses injected fake HTTP: no real OTP, cookies, financial/operational effects or protected fetches. Scenarios are test evidence, not backend/APIM acceptance.

Before activation, separate approval must name: actual nonproduction APIM resource/gateway/tier; distinct exact Customer/Operations origins; route contract; separate host-scoped Secure/HttpOnly `__Host-` cookies with reviewed TTL/SameSite; CSRF header/value; inherited security controls and credential-redacted diagnostics. OW-P0-03 examples remain **PROPOSED — NOT APPROVED**. Origin selects cookie; client roles/product fields cannot select identity. Never reuse Operations cookie or assume shared sign-in.

Real tests must prove credential stripping before JavaScript, cookie creation/expiry, stable refresh, revocation/logout, foreign-origin and cross-product isolation, nonopaque errors, multi-tab Web Locks including stalled operations, actual cold/idle latency and redacted diagnostics. Also confirm deployed business API/CORS/runtime/idempotency retention/reconciliation and approved legal/support/public origin. No Azure provisioning/deployment, paid service, production credential or real login was initiated.
