## Activation / error contracts

Raw Phase 1O auth routes remain backend authority but are never called directly: raw verify/refresh expose refresh credentials. App-local APIM adapter implements challenge, stripped four-field access grant, cookie refresh and confirmed logout with configuration/origin/CSRF checks and cross-tab serialization. Production still composes unavailableAdapter/null origin. Issues #13/#14 and actual gateway/browser acceptance remain blocking.

APIM example paths/cookies/headers remain **PROPOSED — NOT APPROVED**. Resource, exact separate origins/cookies, CSRF, redacted diagnostics and environment approvals are required. Razorpay needs approved nonproduction origin/test merchant, CSP/frame/connect policy and actual checkout acceptance. Optional map/geocoder hosts require privacy/attribution approval; no default location-query provider.

401: one coordinated refresh/exact replay. 403: no refresh. Known safe 409 codes: refetch/review; unstructured conflict stays conservative. 422: input; 429: explicit retry. 5xx/network/timeout/malformed success: retain ambiguity. Raw errors/provider data never reach UI/logs. Live activation also requires deployed CORS/API/idempotency retention/reconciliation evidence. No resource, policy or production environment was deployed.
