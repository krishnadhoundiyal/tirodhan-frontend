Address DTO exactly: `address_id,label,address,location,status,is_default,version`. Address length 1–2000; nullable label <=80; nullable finite latitude −90…90 and longitude −180…180; boolean default; ACTIVE/ARCHIVED; positive integer version. UI creates with null location and preserves existing coordinates on edits; no location permission request.

Context DTO exactly: `serviceability_context_id,source_address_id,source_address_version,status,cell_id,failure_code,expires_at,resolved_at`. Saved source ID/version must both be present. Actual statuses: PENDING, SERVICEABLE, UNSERVICEABLE, TECHNICAL_FAILURE. PENDING has no terminal fields; SERVICEABLE needs a cell; technical failure needs failure code; terminal states need resolved_at. Aware timestamps required. Expired/changed are local validity states, not invented backend statuses. Cell/failure codes are not rendered or logged.

Errors: 401 one coordinated refresh/replay preserving exact body/key; 403 no refresh; 404 missing/not-owned; 409 version/default/key/in-progress conflict (also invalid serviceability input); 422 validation; 429 rate limit; 503 runtime/protection/retention unavailable. Raw backend/provider details are not parsed or displayed. Network, timeout and malformed successful response have controlled copy.

Uncertain writes, including unstructured 409, retain exact commands and lock replacement input. A 409 does not prove a version conflict. Explicit identical retry is available, with no automatic replacement/overwrite. Forms and archive/check commands survive account sub-navigation; logout clears them. Document reload loses recovery. Before live writes, confirm the deployed idempotency retention window and reconciliation behavior; no durable personal-data queue is introduced.

## Authentication protocol

Actual raw Phase 1O routes: POST `/v1/auth/otp/start` (202; client_request_id + phone → challenge), `/otp/verify` (200; client_login_id + challenge_reference + code → access **and refresh** credentials), `/refresh` (200; refresh credential body), `/logout` (204; refresh credential body). Stable refresh does not rotate or extend session expiry. Customer Web **never calls these raw routes**. The injected adapter expects a challenge, stripped four-field access grant and confirmed logout; cookie adaptation remains separately gated APIM work.

Sources: `api/routes/{auth,addresses,serviceability}.py`, `api/dependencies.py`, `modules/{identity,customers,serviceability}/service.py`, identity tokens/models and reliability primitives. Mobile address form/queries, collection repository, serviceability state and all four requested contract/report references were inspected. No backend file/configuration/test/branch was modified.
