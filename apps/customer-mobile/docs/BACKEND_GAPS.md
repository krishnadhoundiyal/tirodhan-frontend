## Temporary mutation header mismatch

Backend requires `Idempotency-Key` for address create/update/archive, serviceability create, collection cancel and payment attempts. Address/serviceability/payment routes declare a required header; cancel manually rejects missing headers with 400. Collection create instead uses its defined `client_request_id`. OTP start/verify use their defined command IDs.

Frozen frontend handoff forbids a generic persistent idempotency subsystem. The user explicitly permits temporary adaptation at the transport boundary. `Transport.command()` therefore allocates a random request-scoped header only for the six verified legacy route patterns. Feature code cannot supply keys. A prepared command snapshots its body and reuses its header during the one 401 replay and explicit retry of that same in-memory command. Address form retains the command on an ambiguous failure; changed input creates a new intent. Mutations never automatically retry network/5xx failures. Nothing is stored in a local database/ordinary storage, and there is no durable queue.

This is a documented temporary compatibility measure, not a permanent architecture decision. Backend/frontend owners must resolve the mismatch before production release. Process death loses the temporary command: do not promise safe persistent replay of an uncertain mutation.

## Semantics preserved

- GET serviceability only reads persisted state; it never resolves on the mobile device. PENDING may resolve asynchronously or synchronously inside collection creation. No H3 derivation or mobile serviceability computation.
- Address PUT includes the server's `expected_version`; conflict copy asks the user to refresh rather than overwriting silently.
- Pricing is returned by collection creation. Optional quantity and gram declarations pass through unchanged.
- Server webhook remains financial authority. The app never invokes payment provider webhooks or creates a local captured-payment state.
- Push is a navigation/refetch signal. Unknown payloads fall back to Activity; arbitrary URLs, payload statuses and PII are ignored. Every app resume refreshes queries even if no push arrived. Duplicate taps suppress repeated navigation but still invalidate server reads.
